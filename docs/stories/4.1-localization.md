## 1. User story

> **As** a player who has set the game to one of its own languages,
> **I want** the mod's screens, prompts and messages to switch to that language with the game,
> **so that** I can read what a treaty, a grievance or a mission will cost before I pay it.

> **As** a community translator,
> **I want** to copy one folder, change its name and translate one column,
> **so that** I can ship a language without touching the mod's code.

## 2. Why

Today `ModuleData/Languages/EN/std_module_strings.xml` holds two strings. About **1,300**
player-facing literals (42k lines, 2026-10-03 count) sit in code and prefabs with no key, so no
translation can reach them. The mod's prices, odds and bands are the point of the design; a player
who cannot read them cannot use the mod. The game already offers 13 languages, and a player who
has chosen one expects every mod to follow it.

## 3. Scope

**In**
- Every string a player can see: Gauntlet prefabs (Realm, Court, Intelligence tabs, Encyclopedia
  court page, peace table), view-model text, inquiries, notifications and log-to-screen messages,
  tooltips, MCM setting names and descriptions, the main-menu warning, the Nexus/Workshop copy.
- `EN` as the complete source file set, and a translation for each of the game's own 13 languages
  (ST-8): `EN`, `BR`, `CNs`, `CNt`, `DE`, `FR`, `IT`, `JP`, `KO`, `PL`, `RU`, `SP`, `TR`. Read from
  `Modules/Native/ModuleData/Languages` on the installed game (2026-10-03), **minus `VI`**: that folder
  is a community Vietnamese patch, not the game's (its files date from 2026-07-12, while the official
  languages were rewritten by Steam on 2026-10-02, and it needs the `FontVietHoa` mod's font).
- A check that fails the build when a converted area regresses (ST-6).
- A one-page guide for community translators (ST-9).

**Out**
- **Log lines, telemetry, `diplomacy.*` command names and their output, exception text.** These
  are for the lead and for tools such as `analyse-log.py`; they stay English.
- Design docs and code comments (English by CLAUDE.md §4).
- Any language the game itself does not offer. The mod follows the game's language setting and adds
  no selector of its own.
- Right-to-left layout (the game offers none) and font work: the CJK languages use the game's own
  fonts, which ST-1 confirms for a mod's strings.

## 4. Business rules

| # | Rule |
|---|---|
| R1 | **Source form.** A translatable string is `new TextObject("{=DI_<area>_<slug>}English text")`, with the English as the fallback. A missing key degrades to English, never to a blank or a raw key |
| R2 | **Keys are stable identifiers, not text.** A wording fix keeps its key; a change of *meaning* gets a new key, so no translation silently says something the English no longer does |
| R3 | **No sentence is built by joining fragments.** A sentence with a number, a name or a term is one string with named variables (`{AMOUNT}`, `{KINGDOM}`), so word order can change per language |
| R4 | **Variables are validated.** Every translation carries exactly the `{VARIABLES}` its English source has |
| R5 | **No hidden text.** A number shown in the UI is still the number the AI used (CLAUDE.md §3); translation changes words, never values or rules |
| R6 | **No throw crosses the engine.** Text lookup failing answers the English fallback and logs once |
| R7 | **English must not change.** With the game in English, every converted surface reads exactly as before (AC1) |

## 5. Acceptance criteria

**AC1 — English is unchanged**
- Before the conversion, record every converted surface's English text (a golden file from the
  extraction tool, plus screenshots of the Realm, Court, Intelligence and peace-table screens).
  After: the same text, character for character, in the same screens.

**AC2 — A second language really switches**
- With a vanilla language selected in the launcher, the converted screens show it, and switching
  back to English restores English. Checked on three: `DE`, `RU` and `CNs`. With a key deleted from
  one language's file, that one string shows English and nothing else changes.

**AC3 — Prefab text is covered**
- Every visible string in `GUI/Prefabs/**` is either behind a key or listed, with the reason,
  in ST-1's findings. No panel mixes languages.

**AC4 — Variables survive**
- A string with `{AMOUNT}` or a name renders the real value in both languages. A translation with
  a missing or extra variable fails ST-6's check.

**AC5 — The guard holds**
- `check-localization.ps1` (ST-6) fails on: a duplicate key, a key in code with no `EN` entry, an
  `EN` entry used nowhere, a variable mismatch between languages. `build.ps1` and `deploy.ps1` run it.
  `check-save-ids.ps1`, the `Harmony patched N methods` line and the save-data ids are unchanged.

**AC6 — Fit**
- The screens are checked in game at the shipped resolutions in the longest language (`DE` or `RU`)
  and a CJK one (`CNs`): no clipped button, tab or tooltip, and no missing glyph. Anything that does not fit is fixed in the translation first, the layout second.

**AC7 — A translator can start**
- A person who has never seen the repo can fix or improve one language from the guide alone (ST-9),
  tested by following it once from scratch on a copy of one language folder.

**AC8 — Release**
- `release.ps1`'s zip and the Workshop stage contain every `Languages/*` folder. The Nexus and
  Workshop pages say which languages ship and how to add one.

## 7. Decisions

The lead's requirement (2026-10-03) is one sentence: *when a player switches the game to a language
the game already offers, the mod's text switches with it, and a new language can be added.* The
four calls below follow from it and were delegated to the tech lead.

| # | Question | Answer |
|---|---|---|
| D1 | When? | **Now, ST-1 first as a gate.** Phase 3 is accepted and the three pillars' text is mostly settled; each week of delay adds literals that must be converted later. Balance edits change numbers, rarely wording. TODO's earlier "after 1.0's balance" is superseded. If ST-1 shows prefabs cannot take keys, report before ST-4 starts |
| D2 | Which languages | **Revised 2026-10-03 (lead): the game's own languages only.** The mod follows the game's language setting. Vietnamese is **not** one of them: it is a community patch (`VI` folders added by hand to each official module, plus the `FontVietHoa` font mod), so it is out of this story. A Vietnamese player of that patch gets English from us until a `VI` folder is added the same drop-in way; it would also need their font mod to draw the accents, which we cannot ship. Honest cost: the lead cannot review any of the 12 translations, so all are labelled machine drafts and corrected by native speakers by pull request (D3) |
| D3 | Where do translations live? | In the repo under `ModuleData/Languages/<code>/`, shipped in the release zip and the Workshop item. Corrections come from the community by pull request |
| D4 | Pause feature work during ST-4? | No. From the day ST-6 exists, new player-facing text is written with a key, so the backlog stops growing |

## 8. Risks

| Risk | Mitigation |
|---|---|
| Prefab text cannot be keyed directly | ST-1 finds out first, before 1,300 edits are committed to |
| The extraction tool rewrites something that is not player-facing (a log, a command id) | Dry-run report reviewed by hand; AC1's golden file; ST-2's boundary rule |
| Translations drift from the English after balance edits | R2 and R4, and ST-6 flagging a variable mismatch |
| A longer language (German, Russian) overflows a fixed-width tab or button | AC6 in game; prefer shortening the translation to widening the layout (the Kingdom-UI loose ends in TODO are the same pressure) |
| Machine-drafted text misleads a player about a price or a rule | The numbers are variables, never translated text (R5); drafts are labelled on the pages; a reported bad line is fixed by pull request. The check cannot judge meaning, only structure |
| CJK glyphs missing in a mod's strings | The game's own fonts serve those languages; AC6 checks `CNs` in game. Right-to-left is not offered by the game |
| A key edited in the middle of a long run breaks a save | It cannot: no string is saved, and the story touches no save data (`check-save-ids.ps1` unchanged) |

## 9. ST-1 — findings

**Read from the installed game, 2026-10-03 (not yet run in game):**
- Vanilla's language folders: `BR CNs CNt DE FR IT JP KO PL RU SP TR`, plus English at the root
  (`Native/ModuleData/Languages`). Thirteen with `EN`. `VI` is also there but is a community patch
  (see Scope), so it is not counted. An earlier version of this story counted it and said 14.
- Mods ship per-language folders under `ModuleData/Languages/<code>/`, each holding a
  `language_data.xml` and a strings file. Bannerlord.ButterLib is the model: `DE/language_data.xml`
  is `<LanguageData id="Deutsch" name="Deutsch" subtitle_extension="de" supported_iso="..."
  under_development="false">` with one `<LanguageFile xml_path="DE/<file>.xml"/>`, and the file is
  `<base><tags><tag language="Deutsch"/></tags><strings><string id=".." text=".."/>`. Vanilla's own
  `language_data.xml` for a language lists its files the same way, so the `id`, `name` and ISO list
  are copied from vanilla's entry for that language.
- Our `EN` folder today has a strings file and **no `language_data.xml`**: add one.
