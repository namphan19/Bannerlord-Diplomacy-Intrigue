## 1. User story

> **As** a Vietnamese player who runs the community Vietnamese patch,
> **I want** the mod's screens and messages in Vietnamese when the game is set to Vietnamese,
> **so that** I can read what a treaty, a grievance or a mission costs before I pay it.

## 2. Why this is its own story

Vietnamese is **not** one of the game's own languages (4.1 §3). What exists on this machine, read
2026-10-03:

- A **community patch** that put a `VI` folder into every official module (`Native`, `SandBox`,
  `SandBoxCore`, `CustomBattle`, `StoryMode`, `Multiplayer`, `NavalDLC`). Its
  `language_data.xml` declares `id="Vietnamese" name="Tiếng Việt" subtitle_extension="vi"
  supported_iso="vi,vie,vi-VN"`. Its files date from 2026-07-12; Steam rewrote the official languages
  on 2026-10-02, which is how the difference shows.
- A **font mod**, `FontVietHoa` (module id `ModTiengViet`, written for v1.4.5), whose
  `GUI/Fonts/vhLanguages.xml` maps the game's fonts to `VNFont` for the language `Vietnamese`. Without
  it the accents do not draw.

So the language's existence, and the font that draws it, belong to other people's mods. This story
adds our strings to that language and takes care not to disturb either.

## 3. Scope

**In**
- `ModuleData/Languages/VI/` for our mod: a `language_data.xml` and a strings file with the same key
  set as `EN`, in the same shape as the other languages of 4.1 §9.
- A Vietnamese translation by the `vietnamese-writing` skill and its glossary, **reviewed by the lead**.
- Wording that matches the patch's own Vietnamese for terms the game already has, so the mod reads
  like the game it sits in.
- A note on the pages: needs the Vietnamese patch and its font mod; neither ships with us.

**Out**
- Shipping, copying or editing the patch's strings or the font. They are someone else's work; the
  Nexus/Workshop pages link to them at most.
- Any change to the patch's own files in the game folder. `VI` of ours lives in our module only.
- Other languages (story 4.1).

## 4. Business rules

| # | Rule |
|---|---|
| R1 | **One key set.** `VI` has exactly the keys and `{VARIABLES}` of `EN` (4.1 R4). The check of 4.1 ST-6 runs on it like any other language |
| R2 | **No font, no claim.** Our module ships no font and no glyph data. If the player has no Vietnamese font mod, the accents may not draw; that is documented, not worked around |
| R3 | **Same terms as the game.** A term the patch already translates (kingdom, clan, influence, treaty, war, peace, party, army, siege, fief) is rendered the way the patch renders it, found by id in its `std_*_xml-VI.xml` files; our own terms (Hold, hegemon, grievance, casus belli, court, legitimacy, pretender, handler) go in the project glossary once and are used everywhere |
| R4 | **Values are not text.** Prices, odds and bands are variables (4.1 R5); the translation changes words only |
| R5 | **Inert without the patch, or provably harmless.** Whether a `VI` folder of ours is ignored when no Vietnamese language exists in the game is not known (ST-1). It must not make the game list a half-working "Vietnamese" |

## 5. Acceptance criteria

**AC1 — It switches**
- With the patch and the font mod active and the game set to Vietnamese, every converted screen of
  4.1 shows Vietnamese with correct accents. Switching to English restores English.

**AC2 — Without the patch, nothing appears**
- On a game without the Vietnamese patch (a second install, or the patch's `VI` folders moved aside
  on a test copy), the language list is unchanged and the mod shows English. If the list gains a
  Vietnamese entry, the story stops and reports (R5).

**AC3 — The lead reads it and accepts it**
- The lead reviews the file screen by screen in game. Each line they reject is changed and listed in
  §9. A list of terms the lead chose goes into the glossary.

**AC4 — It fits**
- Vietnamese is longer than English in several labels. No clipped button, tab or tooltip at the
  shipped resolutions; a clipped one is shortened in the translation first, the layout second.

**AC5 — The guard holds**
- `check-localization.ps1` passes on `VI`: same keys, same variables, no duplicate. `check-save-ids.ps1`
  and the `Harmony patched N methods` line are unchanged.

**AC6 — The pages say what it needs**
- The Nexus and Workshop pages state that Vietnamese needs the community patch and its font mod, and
  name which; the Vietnamese handbook says the same.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Our `VI` folder creates a second, broken "Vietnamese" for players without the patch | ST-1(b) and AC2 before anything is shipped |
| The patch changes its language `id` or file names in a later version | R5 and ST-1 record what was read and when; the check cannot catch it, so a note in the handbook says which patch version was tested |
| The patch was written for v1.4.5 and may not match the game version a player has | Not ours to fix; AC1 is verified on this machine's version and says so |
| The font mod's glyph set lacks a character we use (a typographic dash, a symbol) | AC4 looks at every screen; offending characters are replaced in the translation |
| Vietnamese labels overflow tabs and buttons | AC4; shorten the translation first |

## 9. Findings

### ST-1 — spike: part done on disk, the live half not done

**(a) The patch is alive on this game version, and its ids still match.** Its `language_data.xml`
declares `id="Vietnamese" name="Tiếng Việt" subtitle_extension="vi" supported_iso="vi,vie,vi-VN"`,
and it put a `VI` folder into seven modules (`Native`, `SandBox`, `SandBoxCore`, `CustomBattle`,
`StoryMode`, `Multiplayer`, `NavalDLC`). Its string ids are **hashed**, so a term cannot be looked up
by id; joining each VI file to the English base file of the same name yields **23,808 strings**, which
means the hashes still line up with vanilla's on this install. The patch's files date from
2026-07-12 and Steam rewrote the official languages on 2026-10-02, so this is worth having checked.

Two things found while reading it:
- **Vanilla has no `EN` folder.** English is the base file sitting directly in
  `ModuleData/Languages/`, and every other language is a subfolder. Reading `Languages/EN/…` finds
  nothing, which is how the first run of the term-sheet script joined zero strings and looked like
  the patch's ids were stale. They are not.
- **The patch's own `language_data.xml` names one file without its suffix**: `VI/std_photo_mode_strings_xml.xml`.
  Harmless (the base file has the same name) and not ours to fix.

**(c) What our `language_data.xml` must carry.** The `id` is what has to match: a language is keyed
by it, so ours must be `id="Vietnamese"` to join the patch's language rather than define a second
one. `name`, `subtitle_extension` and `supported_iso` are what the launcher shows and filters on;
whether they must match the patch's exactly is **not yet established**, and it is cheap to get wrong
in a way that produces two Vietnamese entries.

**(b) NOT DONE, and it is the stop condition.** R5 and AC2 ask what happens on a game **without** the
patch: is our folder ignored, or does it add a half-working "Vietnamese" to the list? A language is
built from the `language_data.xml` files the game finds in modules, so the likeliest answer is that
ours *would* appear — which is AC2's stated failure. **This cannot be settled without a second
install or a copy of the game folder**, and it is the one finding that can stop the story. It is
**open**, and it is why no `VI` folder has been written into the module yet.

The live half of (a) — whether the game reads *our* `VI` strings when the patch is present, and
whether switching to Vietnamese shows Vietnamese — is also **open**, because the game's language
lives in the official launcher's UI and nothing on this machine reaches it (4.1 §6a).

### ST-2 — term sheet, and the trap in it

`scripts/term-sheet.ps1` reads the patch's files, joins them to the English base by hashed id and
writes `scripts/term-sheet.md`. The glossary at `.claude/skills/vietnamese-writing/references/glossary.md`
now carries the confirmed terms, and the sheet says which of them the patch translates at all.

**`Hold` is a trap.** The patch translates `Hold` as **"Giữ"**, because in the game `hold` is the
verb "to hold". Our `Hold` is a different thing - the bond between a vassal and its patron - and
following the patch there would produce a word that means nothing here. Kept as `Hold`.

**Five conflicts for the lead (D3).** The default is to follow the patch; these are the political
concepts where that may be wrong:

| | patch | our old glossary |
|---|---|---|
| town | Thị trấn | thành phố |
| fief | lãnh thổ (prose) / lãnh địa (tab) | thái ấp — the patch itself uses three words |
| ruler | Người cai trị | vua |
| realm (our tab) | nothing | — |
| court (our tab) | nothing | — |

**Ten terms the patch does not have at all**, so they are entirely ours: hegemon, grievance, casus
belli, handler, counter-intelligence, treasurer, manor, settler, Hold-as-concept, and our two tab
names.

**One correction to the glossary itself.** Its "keep it in English" list (tab names, band names) was
written for **prose**, where naming the English label a player sees is right. It must **not** be
applied to `Languages/VI/di_strings.xml`: a player running the patch sees Vietnamese on every vanilla
label, so an English tab name of ours would read as an intrusion. The glossary now says which is
which.

### ST-3 to ST-7 — not started

ST-3 is 852 keys. It is gated on the five decisions above, because a term chosen wrong has to be
changed in every sentence that uses it.
